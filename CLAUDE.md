# Rehearse — Project Orientation

Rehearse is a **local-first runner for GitHub Actions workflows**. It reads
`.github/workflows/*.yml` and executes them on a developer machine —
two backends (host subprocess, container via Docker), parallel matrix
via per-cell git worktree, real `actions/cache` semantics, watch mode,
pre-push hook, JS-action runtime, local + remote composite actions, and
local reusable workflows. Free, Apache 2.0, source on
[github.com/plsft/rehearse](https://github.com/plsft/rehearse).

## Repo layout

| Path | What | Status |
|---|---|---|
| `cli/` | `@rehearse/cli` — the runner and the `rh` CLI (run workflows, compile TS pipelines) | npm, Apache 2.0 |
| `ts-ci/` | `@rehearse/ci` — TypeScript SDK that compiles to GitHub Actions YAML | npm, Apache 2.0 |
| `git-engine/` | `@rehearse/git-core` — pure-TypeScript git engine. Internal and frozen since v0.6.0: not published, not in the pnpm workspace, not tested in CI. The runner uses native `git` for clones. | private |
| `site/` | Marketing site at [rehearse.sh](https://rehearse.sh) (deploys as `rehearse-web` Workers Static Assets) | private |
| `bench/` | Cross-OS benchmark harness (runner vs `act` vs GitHub-hosted) | private |
| `poc/` | Test fixtures (`poc/fixtures/*.yml`) and a hono clone (`poc/playground/hono`) used by the bench | private |
| `scripts/` | `release.mjs` is a retired stub (exits 1). Releases are automated by release-please | private |
| `.rehearse/pipelines/` | Our own CI pipelines authored in TypeScript (compiled to `.github/workflows/`) | private |
| `.github/workflows/` | Auto-generated by `rh ci compile` from `.rehearse/pipelines/`. Do not edit by hand | generated |
| `release-please-config.json`, `.release-please-manifest.json` | release-please config (single root component; `cli` + `ts-ci` bumped in lockstep via `extra-files`) | config |
| `commitlint.config.mjs`, `.githooks/` | Conventional-commit lint (`@commitlint/config-conventional`) and the tracked pre-push hook that runs it | config |

## Current state

- 2 packages on npm, Apache 2.0: `@rehearse/cli` and `@rehearse/ci`, versioned
  in lockstep (current version is in `cli/package.json`; release-please bumps it)
- Tests: `cli/test/` (`pnpm --filter @rehearse/cli test`) and `ts-ci/test/`
  (`pnpm --filter @rehearse/ci test`). CI runs only the ts-ci tests plus
  typecheck; the cli suite is not in CI yet (the bundled `dorny/paths-filter`
  `dist/` is gitignored, and the compat test needs a prior build)
- Benchmarks vs `act` (and nightly compat results): `bench/RESULTS.md`, `bench/compat/`

## Working in this repo

- Build everything: `pnpm turbo build`
- Test the cli: `pnpm --filter @rehearse/cli test`; the SDK: `pnpm --filter @rehearse/ci test`
- Run the runner against a workflow: `node cli/dist/index.js run <workflow>`
- Recompile workflows after editing `.rehearse/pipelines/`: `pnpm pipelines:compile`
- Bench: `pnpm tsx bench/compare.ts --skip-cold`
- Commits must be [conventional](CONTRIBUTING.md#conventional-commits)
  (`type(scope): subject`). `pnpm install` enables `.githooks/pre-push`, which lints
  pushed commits; PRs are squash-merged and the PR title is linted by CI.
- Releases are automated: merge the standing release-please PR
  (`chore(main): release X.Y.Z`); CI tags, creates the GitHub Release and
  publishes to npm. Never run `pnpm release` (retired). Force a version with a
  `Release-As: x.y.z` commit footer
  - The release PR is opened with `GITHUB_TOKEN`, so **no CI runs on it**. Build
    and `pnpm pack` (run inside `cli/` and `ts-ci/`) the merged result locally
    before merging it.
  - npm auth is trusted publishing (OIDC), not a token (#11). Each package has a
    trusted publisher on npmjs.com (repo `plsft/rehearse`, workflow `release.yml`)
    and the `publish` job has `id-token: write`. **Don't rename `release.yml` or
    move the publish step into a reusable workflow** without updating both
    trusted publishers, or publishing breaks. If publish fails, fix the cause and
    use **Re-run failed jobs**; it skips versions already on npm. npm can take
    about 2 minutes to show a new version.
- The PR title becomes the squash commit on `main`, so it decides whether a
  release is cut. Use `fix(deps)` only for runtime dependency bumps in `cli/` or
  `ts-ci/`. Tooling, docs and hook changes use `chore`/`ci`/`docs`, never `fix`.
- Dependabot's GitHub Actions bumps edit only the generated
  `.github/workflows/*.yml`. Make the same bump in `.rehearse/pipelines/*.ts`
  in that PR, or the next `pnpm pipelines:compile` reverts it.
- Compiling on Windows rewrites the `# Source:` header in the generated YAML
  with backslashes. Don't commit a diff that only changes that header.
- Deploy the marketing site: from `site/`, `npm run deploy` (vite build + wrangler deploy to `rehearse-web` Worker)

## History

The project was originally an agent-governance / git-hosting platform.
It pivoted in May 2026 to a local-first GitHub Actions runner because
the runner was the strongest asset and had the clearest path to
traction. The TypeScript git engine (`@rehearse/git-core`) and the
TypeScript CI authoring SDK (`@rehearse/ci`) survived the pivot and
ship today as the foundation under the runner. Pre-pivot history is
in `git log` if you need archaeological context.
